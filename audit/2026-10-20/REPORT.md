# 博客功能清理与 Decap 验证报告

> 这是清理前的历史审查报告。已实施的修改和最终验证结果见 [IMPLEMENTED.md](IMPLEMENTED.md)。

日期：2026-10-20。状态：供审查；没有执行功能删除，没有提交或推送 GitHub，没有修改线上服务。

## 结论

Decap 可以承接目前的文章文件和图片工作流，但需要针对这个博客配置。普通图文适合富文本编辑；音乐文章中的自定义语法和复杂 MDX 应先使用源码模式。现成后台不能直接提供与 Astro 一致的音乐卡片或 MDX 实时预览，也还没有实现音乐卡片插入表单。

项目值得清理。最直接的残留是：Exhibition 聚合页已经不生成，但相册、日记、动画、项目、技能、时间线等独立页仍在生成。应根据下面的功能清单决定删除范围，不能仅依据导航里是否可见或配置是不是 false。

## 第二步：Decap 代表文章验证

### 隔离方式

没有将本地后台连接到真实 GitHub 仓库。使用官方 Decap 浏览器包、官方 decap-server 文件代理和文章副本；文件代理仅监听 127.0.0.1。测试“Publish now”只写临时目录。隔离站点不复制 `.env` 或 Git 凭据。

先验证配置标称版本 3.9.0，再核实原集成实际使用 `^3.9.0` 浮动地址，当前会解析到 3.17.1，并补测后者。正式接入建议固定精确版本，升级后再检查内容往返。代理工具版本为 decap-server 3.11.5。

### 代表文章与结果

| 样本 | 验证动作 | 结论 |
| --- | --- | --- |
| 普通图文：`to-feel-not-fight/index.md` | 修改描述，切换源码/富文本，编辑正文并保存；检查 2 个相对图片引用 | 通过；富文本会规范化 Markdown，例如 `---` 变为 `- - -`，渲染仍为分隔线 |
| 音乐文章：`happy-new-year-2026/index.md` | 富文本保存对照；恢复后用固定源码模式编辑保存 | 自有音乐卡片仍生成；默认富文本会破坏该文 2 处 spoiler 的语义。源码模式保留音乐块、歌词和全部扩展语法 |
| 复杂 MDX：`full-platform-music-players-cloud-local/index.mdx` | 明确 Frontmatter 格式后加载；分别测试富文本和源码保存 | 本样本两种方式均可构建；11 条图片 import、12 个 JSX 图片及网格布局被保留。仍推荐源码模式，不能据此保证任意 MDX 都可富文本编辑 |
| 新建文章与图片 | 在 UI 新建 Decap Audit Bundle，上传 image.png，选为封面并作为正文图片插入后保存 | 自动生成 `decap-audit-bundle/index.md` 和同目录 `image.png`；正文引用为 `![Audit uploaded image](image.png)`；上传文件与原图逐字节相同 |

高级文章的源码模式保存后，去掉本次追加的验证标记，正文与原文完全一致；原有 Frontmatter 字段值也一致。普通文章仅故意修改描述，其余原有字段值保留。

### 富文本兼容问题的实际影响

音乐文章原文 `:spoiler[内容]` 被默认 Markdown 富文本序列化器写为 `:spoiler\[内容]`。

此改写在 3.9.0 和本次实际解析到的 3.17.1 中均已通过浏览器编辑保存复现。3.17.1 下的普通文章富文本、音乐文章源码、MDX 源码保存也均补测通过。

隔离构建后，原本应包含文字的两个 `<spoiler>` 节点变成空节点，文字位于节点之外。音乐卡片仍有 1 个，不能只检查卡片存在或“构建成功”就判定整篇文章没有变化。

候选配置对音乐文章和 MDX 使用 `modes: [raw]`，避免自动经过富文本转换。更方便的可视化卡片表单需要后续适配；本次没有把这项描述成已经完成。

### 接入配置需要修正的地方

- 现有仓库/域名仍是模板作者的值，GitHub OAuth 关闭；本次没有改这些生产设置。
- 现有 Posts 默认扩展是 md，MDX 需要单独明确扩展与 Frontmatter 格式；测试时未明确格式的 MDX 文件曾显示为空，补充配置后正常读取。
- 当前配置未向编辑者提供 directoryTitle 等个人扩展字段；正式配置应按内容 schema 对齐，并保留未展示字段。
- 对省略 `draft` 的旧文章，布尔字段若作为必填会阻止保存。本次在候选配置将其设为可选；保留新文章默认 false。
- 新文章需要设置 `path: '{{slug}}/index'`，并使用相对媒体目录，才能按实测方式自动管理文章和图片。
- 样本集合采用显式文件路径，便于限制测试范围；附带配置是验证夹具，不是能直接上线的完整文章管理配置。

### 预览与正式发布的边界

普通文字与图片能显示在 Decap 预览中。默认预览不执行本站的 Astro 插件；音乐卡片显示为自定义语法，MDX 不会执行 import 和 JSX，不能作为最终页面效果。

正式接入仍需完成 GitHub 登录认证、真实仓库授权和一次受控发布验证。本次没有声称 OAuth、GitHub 提交或远端自动部署已经测试通过。
